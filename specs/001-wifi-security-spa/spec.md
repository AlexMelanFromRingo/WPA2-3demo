# Feature Specification: Интерактивная методичка по безопасности Wi-Fi (WPA2/WPA3/Hashcat 22000)

**Feature Branch**: `001-wifi-security-spa`
**Created**: 2026-05-20
**Status**: Draft
**Input**: User description: "Интерактивное одностраничное веб-приложение для изучения безопасности Wi-Fi. Модуль 1 — WPA2 4-Way Handshake (PMK → обмен ANonce/SNonce → сборка PTK → создание MIC). Модуль 2 — WPA3 SAE (Dragonfly): превращение пароля в элемент эллиптической кривой (PWE) и почему перехват невозможен. Модуль 3 — симулятор Hashcat (режим 22000) с переключателем типа атаки PMKID / EAPOL. Общее: кнопки «Шаг вперёд/назад», инспекция промежуточных hex-дампов."

## Clarifications

### Session 2026-05-20

- Q: Глубина Модуля 2 (WPA3 SAE) — концептуальная визуализация или реальные криптографические вычисления? → A: Полная криптографическая точность — реальный вывод PWE на стандартной кривой P-256, настоящие обмены Commit/Confirm, числовые значения сверяются с эталонными тестовыми векторами; тяжёлые вычисления выносятся из UI-потока.
- Q: Точность вычислений в симуляторе Hashcat (Модуль 3) — реальный PBKDF2/HMAC для каждого слова или имитация? → A: Реальные вычисления для каждого слова-кандидата (все числа настоящие) и дополнительно режим ускоренного перебора для больших словарей (пропуск анимации промежуточных слов, числа остаются реальными).
- Q: Режим прохождения шагов — только вручную или с авто-проигрыванием? → A: Ручное прохождение («Шаг вперёд/назад») плюс режим авто-проигрывания (play/pause) с регулировкой скорости во всех трёх модулях.
- Q: Связь данных между модулями — единый сценарий, независимые или с локальным переопределением? → A: Единый общий сценарий по умолчанию (SSID, пароль, MAC-адреса и др.) плюс возможность локального переопределения параметров в каждом модуле без влияния на другие.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Понять, как WPA2 превращает пароль в ключи (Priority: P1)

Новичок без подготовки в криптографии открывает Модуль «WPA2 4-Way Handshake» и
по шагам проходит весь путь: от ввода пароля сети до момента, когда устройства
доказывают друг другу знание пароля. На каждом шаге он видит простое пояснение,
схему перетекания данных и может заглянуть в промежуточные значения.

**Why this priority**: Это смысловое ядро методички. Понимание цепочки
«пароль → PMK → PTK → MIC» необходимо, чтобы вообще понять, что атакует Модуль 3
и что защищает Модуль 2. Без этого модуля остальные теряют учебный смысл.

**Independent Test**: Реализовать только Модуль 1. Тестовый пользователь
проходит все шаги кнопками «вперёд/назад», читает подсказки, открывает hex-дампы и
после прохождения способен своими словами описать, как пароль сети становится
ключом шифрования. Это уже самостоятельный полезный продукт (MVP).

**Acceptance Scenarios**:

1. **Given** открыт Модуль 1 с заданными SSID и паролем, **When** пользователь
   нажимает «Шаг вперёд», **Then** показывается шаг вывода PMK с всплывающей
   подсказкой, схемой потока данных «вход → преобразование → выход» и доступным для
   просмотра hex-дампом.
2. **Given** пользователь находится на шаге обмена nonce, **When** он нажимает
   «Шаг назад», **Then** он возвращается к предыдущему шагу, а все ранее введённые
   параметры и вычисленные значения сохраняются.
3. **Given** пользователь правит пароль в поле ввода, **When** он продолжает
   набирать текст, **Then** интерфейс остаётся отзывчивым без подвисаний, а
   зависимые значения пересчитываются в фоне с индикатором прогресса.
4. **Given** достигнут шаг создания MIC, **When** пользователь открывает hex-дамп,
   **Then** отображаются промежуточные значения (ключ KCK, кадр EAPOL, итоговый MIC)
   в шестнадцатеричном виде.
5. **Given** введён эталонный набор параметров WPA2, **When** пройдены все шаги,
   **Then** значения PMK, PTK и MIC совпадают с эталонными тестовыми векторами.

### User Story 2 — Увидеть, как офлайн-атака подбирает пароль (Priority: P2)

Пользователь открывает Модуль «Симулятор Hashcat (режим 22000)», выбирает тип
атаки (через PMKID или через EAPOL) и наблюдает, как симуляция берёт слова из
мини-словаря, строит из каждого «фейковые» ключи и сравнивает их с перехваченным
дампом — пока не найдёт совпадение или не исчерпает словарь.

**Why this priority**: Это раздел, который пользователь явно отметил как важный.
Он показывает, *зачем* всё это нужно: слабый пароль вскрывается перебором офлайн.
Раздел создаёт мотивацию, но опирается на понятия из Модуля 1, поэтому идёт вторым.

**Independent Test**: Открыть Модуль 3, переключить оба типа атаки, отредактировать
мини-словарь и запустить перебор; убедиться, что симуляция наглядно показывает оба
исхода — «пароль найден» и «пароль не найден».

**Acceptance Scenarios**:

1. **Given** открыт Модуль 3, **When** пользователь выбирает тип атаки «Через
   PMKID», **Then** визуализация показывает, что атакующему достаточно одного пакета
   от роутера (полное рукопожатие не нужно), и показывает сверку PMKID.
2. **Given** выбран тип атаки «Через EAPOL», **When** запускается симуляция,
   **Then** визуализация показывает необходимость перехваченного рукопожатия и
   сверку значения MIC.
3. **Given** искомый пароль сценария присутствует в мини-словаре, **When** перебор
   доходит до этого слова, **Then** система показывает исход «пароль найден» и
   подсвечивает совпавшее слово.
4. **Given** искомого пароля в мини-словаре нет, **When** перебор перебирает все
   слова, **Then** система показывает исход «пароль не найден».
5. **Given** идёт перебор, **When** пользователь инспектирует текущий шаг, **Then**
   доступны hex-дампы сгенерированных «фейковых» ключей и сравниваемых хэшей.
6. **Given** идёт симуляция, **When** пользователь переключает тип атаки, **Then**
   отображаемый путь данных и набор требуемых исходных данных обновляются без
   ошибок и без зависания интерфейса.

### User Story 3 — Понять, почему WPA3 защищает пароль (Priority: P3)

Пользователь открывает Модуль «WPA3 SAE (Dragonfly)» и по шагам видит, как пароль
превращается в элемент эллиптической кривой (PWE) и происходит обмен Commit/Confirm.
Главный вывод модуля: перехватчик не получает ничего, что позволило бы подбирать
пароль офлайн, — в отличие от WPA2.

**Why this priority**: Это смысловая развязка методички (проблема → решение). Она
завершает картину, но методичка приносит основную ценность и без неё, поэтому
приоритет ниже.

**Independent Test**: Открыть Модуль 2, пройти шаги SAE кнопками «вперёд/назад»,
прочитать пояснения и блок сравнения с WPA2; убедиться, что наглядно показано,
почему перехват «хэша пароля» в WPA3 невозможен.

**Acceptance Scenarios**:

1. **Given** открыт Модуль 2, **When** пользователь проходит шаги, **Then**
   показываются преобразование пароля в PWE, фаза Commit и фаза Confirm — каждый шаг
   с подсказкой и схемой потока данных.
2. **Given** показан обмен SAE, **When** пользователь смотрит блок «что видит
   перехватчик», **Then** наглядно показано, что перехваченных данных недостаточно
   для офлайн-перебора пароля.
3. **Given** пользователь хочет сравнить WPA2 и WPA3, **When** он открывает
   поясняющий блок, **Then** простыми словами объяснено, какую уязвимость WPA2
   (из Модулей 1 и 3) устраняет WPA3.

---

### Edge Cases

- Пустой SSID или пустой пароль: система показывает понятное пояснение и не
  переходит к расчётам, не «падая».
- Пароль короче 8 или длиннее 63 символов (ограничение WPA2-PSK): система
  предупреждает пользователя простым языком.
- Не-ASCII символы в SSID или пароле: ввод принимается или явно поясняется
  ограничение, без сбоя интерфейса.
- Изменение входного параметра во время идущей анимации или фонового расчёта:
  текущий расчёт отменяется и перезапускается с новыми данными.
- Нажатие «Шаг назад» на первом шаге или «Шаг вперёд» на последнем: кнопка
  недоступна, ошибок не возникает.
- Авто-проигрывание по достижении последнего шага модуля останавливается на нём
  и не зацикливается.
- Локальное переопределение параметра в одном модуле не влияет на общий сценарий
  и на параметры, отображаемые в других модулях.
- Переключение типа атаки в Модуле 3 во время идущей симуляции: путь данных
  пересобирается, прежний перебор корректно прекращается.
- Искомый пароль сценария совпадает со словом мини-словаря → исход «найдено»;
  отсутствует в словаре → исход «не найдено».
- Очень большой мини-словарь: доступен режим ускоренного перебора (пропуск
  анимации промежуточных слов); интерфейс не подвешивается, итоговые числа реальны.
- Совпадающие MAC-адреса точки доступа и клиента либо одинаковые nonce: расчёт
  выполняется, при необходимости даётся пояснение о нетипичности данных.

## Requirements *(mandatory)*

### Functional Requirements

**Общие требования (оболочка и интерактивность)**

- **FR-001**: Система MUST предоставлять три модуля в одном веб-приложении —
  «WPA2 4-Way Handshake», «WPA3 SAE (Dragonfly)», «Симулятор Hashcat (режим 22000)» —
  с переключением между ними без перезагрузки страницы.
- **FR-002**: Каждый модуль MUST поддерживать пошаговое прохождение с кнопками
  «Шаг вперёд» и «Шаг назад», а также режим авто-проигрывания (play/pause) с
  регулировкой скорости.
- **FR-003**: Кнопка «Шаг назад» на первом шаге и «Шаг вперёд» на последнем MUST
  быть недоступна, не вызывая ошибок.
- **FR-004**: На каждом шаге система MUST показывать всплывающую подсказку,
  поясняющую происходящее максимально простым языком.
- **FR-005**: На каждом шаге система MUST показывать визуальную схему перетекания
  данных «вход → преобразование → выход» с текущими (реальными) значениями.
- **FR-006**: На каждом шаге пользователь MUST иметь возможность просмотреть
  промежуточный hex-дамп используемых значений.
- **FR-007**: Все входные параметры (SSID, пароль, MAC-адреса точки доступа и
  клиента, nonce, слова мини-словаря и пр.) MUST быть редактируемыми пользователем.
- **FR-008**: При изменении входного параметра зависимые промежуточные значения
  MUST пересчитываться, а интерфейс MUST оставаться отзывчивым (без подвисаний)
  во время пересчёта, в том числе во время набора текста.
- **FR-009**: Длительные вычисления MUST сопровождаться индикатором прогресса и
  MUST корректно отменяться/перезапускаться при изменении входных данных.
- **FR-010**: Приложение MUST вести единый общий сценарий (SSID, пароль,
  MAC-адреса и пр.), используемый всеми модулями по умолчанию. Каждый модуль MUST
  позволять локально переопределять параметры, не затрагивая общий сценарий и
  другие модули. Переход между шагами и модулями MUST сохранять как общий
  сценарий, так и локальные переопределения и вычисленные значения.
- **FR-011**: При недопустимых входных данных система MUST показывать понятное
  пояснение простым языком и не прерывать работу сбоем.

**Модуль 1 — WPA2 4-Way Handshake**

- **FR-012**: Модуль 1 MUST пошагово показывать вывод PMK по формуле
  `PMK = PBKDF2(пароль, SSID, 4096 итераций)` с пояснением роли пароля как «секрета»
  и SSID как «соли».
- **FR-013**: Модуль 1 MUST показывать генерацию и обмен значениями ANonce и SNonce
  между точкой доступа и клиентом.
- **FR-014**: Модуль 1 MUST показывать сборку PTK из PMK, MAC-адресов и nonce,
  включая разбиение PTK на составные ключи (в том числе KCK).
- **FR-015**: Модуль 1 MUST визуализировать создание MIC на основе ключа KCK и
  кадра EAPOL.
- **FR-016**: Модуль 1 MUST показывать все четыре сообщения рукопожатия (M1–M4) с
  указанием направления обмена (точка доступа ↔ клиент).
- **FR-017**: Числовые результаты Модуля 1 (PMK, PTK, MIC) MUST совпадать с
  эталонными тестовыми векторами WPA2.

**Модуль 2 — WPA3 SAE (Dragonfly)**

- **FR-018**: Модуль 2 MUST пошагово показывать обмен SAE (Dragonfly):
  преобразование пароля в элемент эллиптической кривой (PWE), фазу Commit и фазу
  Confirm. Все вычисления MUST выполняться по-настоящему на стандартной
  эллиптической кривой P-256 (включая реальный вывод PWE), а получаемые числовые
  значения MUST совпадать с эталонными тестовыми векторами WPA3 SAE.
- **FR-019**: Модуль 2 MUST явно показывать, что перехватчик видит только
  обмениваемые элементы и не получает данных, пригодных для офлайн-перебора пароля.
- **FR-020**: Модуль 2 MUST простым языком пояснять, почему превращение пароля в
  PWE делает перехват «хэша пароля» невозможным, и сравнивать это с WPA2.

**Модуль 3 — Симулятор Hashcat (режим 22000)**

- **FR-021**: Модуль 3 MUST содержать переключатель типа атаки с двумя режимами:
  «Через PMKID» и «Через EAPOL».
- **FR-022**: В режиме «Через PMKID» система MUST показывать, что атакующему
  достаточно одного пакета от роутера (полное рукопожатие не требуется), и
  визуализировать сверку PMKID.
- **FR-023**: В режиме «Через EAPOL» система MUST показывать необходимость
  перехвата рукопожатия и визуализировать сверку значения MIC.
- **FR-024**: Модуль 3 MUST использовать редактируемый мини-словарь слов-кандидатов
  (добавление и удаление слов).
- **FR-025**: Модуль 3 MUST визуализировать перебор: выбор текущего слова из
  словаря, генерацию «фейковых» ключей из этого слова и сравнение полученного хэша
  с перехваченным дампом. Для каждого слова-кандидата вычисления (PBKDF2, HMAC,
  PMKID/MIC) MUST выполняться по-настоящему — все отображаемые числа реальны.
- **FR-026**: Модуль 3 MUST явно показывать оба исхода: «пароль найден» (слово
  совпало) и «пароль не найден» (словарь исчерпан без совпадения).
- **FR-027**: Модуль 3 MUST показывать строку хэша формата 22000 для текущего
  сценария и пояснять назначение её полей.
- **FR-028**: Переключение типа атаки MUST визуально менять отображаемый путь
  данных и набор требуемых исходных данных.
- **FR-029**: Модуль 3 MUST содержать явную пометку об образовательном назначении:
  это симуляция математики атаки, без реального захвата трафика и сетевого
  взаимодействия.
- **FR-030**: Модуль 3 MUST предоставлять режим ускоренного перебора для больших
  словарей: пошаговая анимация промежуточных слов может пропускаться, но сами
  криптографические вычисления и итоговые числовые значения остаются настоящими.

### Key Entities *(include if feature involves data)*

- **Учебный сценарий (параметры сети)**: единый общий набор редактируемых входных
  данных (SSID, пароль, MAC-адреса точки доступа и клиента, ANonce, SNonce),
  используемый всеми модулями; каждый модуль может хранить локальные
  переопределения отдельных параметров.
- **Шаг визуализации**: единица пошагового прохождения — порядковый номер,
  пояснительная подсказка, схема потока данных, входные/выходные значения,
  hex-дамп.
- **Криптографический артефакт**: промежуточное или итоговое значение —
  PMK, PTK и его части (включая KCK), MIC, PMKID, PWE, элементы Commit/Confirm.
- **Мини-словарь**: редактируемый список слов-кандидатов для симуляции перебора.
- **Перехваченный дамп**: данные, которые «видит» атакующий, — PMKID или кадр
  EAPOL с MIC, а также строка хэша формата 22000.
- **Тип атаки**: режим симулятора — «Через PMKID» либо «Через EAPOL».
- **Модуль**: один из трёх разделов методички (WPA2, WPA3 SAE, симулятор Hashcat).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Не менее 80% тестовых пользователей без подготовки в криптографии
  после прохождения Модуля 1 верно описывают своими словами цепочку
  «пароль → PMK → PTK → MIC».
- **SC-002**: 100% криптографических шагов во всех трёх модулях сопровождаются
  всплывающей подсказкой и визуальной схемой потока данных.
- **SC-003**: Ввод текста в любое редактируемое поле не вызывает заметных
  подвисаний интерфейса (визуальный отклик ввода — менее 100 мс) даже во время
  идущего тяжёлого пересчёта.
- **SC-004**: Пользователь может перейти к любому шагу любого модуля кнопками
  «вперёд/назад» и вернуться обратно без потери введённых данных и промежуточных
  значений в 100% переходов.
- **SC-005**: На каждом шаге каждого модуля доступен просмотр промежуточного
  hex-дампа.
- **SC-006**: Симулятор Hashcat для обоих типов атак (PMKID и EAPOL) корректно и
  наглядно показывает оба исхода — «пароль найден» и «пароль не найден».
- **SC-007**: Числовые результаты Модуля 1 (PMK, PTK, MIC) и Модуля 2 (PWE,
  значения обменов Commit/Confirm, итоговый PMK) совпадают с эталонными тестовыми
  векторами WPA2 и WPA3 SAE при 100% проверок.
- **SC-008**: Не менее 90% тестовых пользователей оценивают наглядность методички
  выше эталонных проектов TOTP_demo, rsa16-edu и rust_aes128_demo.
- **SC-009**: Новичок завершает полное прохождение Модуля 1 за 10–15 минут без
  посторонней помощи.

## Assumptions

- Интерфейс и все пояснения — на русском языке (методичка для русскоязычной
  аудитории новичков).
- Приложение работает полностью в браузере, офлайн, без серверной части; данные
  пользователя не передаются наружу и не сохраняются между сессиями.
- Модуль 1 (WPA2) и Модуль 2 (WPA3 SAE) численно точны: все промежуточные и
  итоговые значения вычисляются по-настоящему и сверяются с эталонными тестовыми
  векторами. Модуль 2 выполняет реальный вывод PWE на стандартной эллиптической
  кривой P-256 и настоящие обмены Commit/Confirm; тяжёлые вычисления выносятся из
  UI-потока (см. FR-008, FR-009, FR-018).
- Мини-словарь встроен и предзаполнен несколькими словами; пользователь может его
  редактировать. Размер словаря небольшой (единицы–десятки слов), достаточный для
  наглядной демонстрации.
- Перехваченный дамп для симулятора формируется внутри приложения из редактируемых
  параметров сценария; «настоящий» пароль сценария задаётся отдельно от слов
  словаря, чтобы можно было показать как исход «найдено», так и «не найдено».
- Симулятор Hashcat — строго образовательная симуляция математики офлайн-атаки:
  нет реального захвата трафика, нет сетевого взаимодействия, нет интеграции с
  настоящей утилитой Hashcat (соответствует Принципу V конституции проекта).
- Целевые устройства — настольные браузеры; адаптивная вёрстка под мобильные
  устройства желательна, но вне границ MVP.
- Внешние сервисы и зависимости от сторонних систем отсутствуют — всё выполняется
  на стороне клиента.
