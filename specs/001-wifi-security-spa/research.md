## R1. Криптодвижок: чем считать PBKDF2, HMAC, EC-арифметику

**Decision**:
- **Нативный WebCrypto API** — для PBKDF2-HMAC-SHA1, HMAC-SHA1, SHA-1/SHA-256.
  Используется для Модуля 1 (WPA2) и Модуля 3 (симулятор Hashcat). Все вызовы
  асинхронные (`crypto.subtle.deriveBits` / `sign`) и выполняются внутри Web Worker.
- **`@noble/curves`** (+ `@noble/hashes`) — для эллиптической кривой P-256:
  скалярное умножение, сложение точек, hash-to-curve. Используется для Модуля 2
  (WPA3 SAE / вывод PWE). WebCrypto не отдаёт «сырую» арифметику точек, поэтому
  для SAE нужна отдельная библиотека.
- **`crypto-js` НЕ используется.**

**Rationale**:
- WebCrypto закрывает весь WPA2/22000-функционал нативно, без зависимостей,
  асинхронно и не блокируя UI-поток — это прямо соответствует Принципу IV
  конституции и пункту «WebCrypto где возможно» технических стандартов.
- `@noble/curves` — проверенная (audited), zero-dependency библиотека от
  paulmillr; поддерживает P-256 и hash-to-curve. Минимальная и прозрачная
  зависимость — соответствует требованию конституции «зависимости минимальны и
  прозрачны; криптопримитивы из проверяемых источников».
- `crypto-js` пользователь разрешил опционально («можно использовать»). Мы
  сознательно отказываемся: библиотека **снята с поддержки** (автор прямо
  рекомендует переходить на native crypto), а версии `< 4.2.0` содержали
  CVE-2023-46233 (PBKDF2 по умолчанию в ~1000 раз слабее ожидаемого). Для
  учебного проекта про криптографию неприемлемо тянуть неподдерживаемый
  криптопакет, когда WebCrypto + `@noble/curves` полностью закрывают задачи.
  Это отклонение от пользовательского ввода зафиксировано в Complexity Tracking
  плана.

**Alternatives considered**:
- `crypto-js` для «быстрых синхронных операций» — отклонено (см. выше).
- Чистый WebCrypto без `@noble` — невозможно: нет API для арифметики точек EC,
  требуемой SAE.
- WASM-сборка OpenSSL/libsodium — отклонено: тяжелее, непрозрачнее, избыточно.

## R2. Неблокирующая архитектура (Принцип IV — NON-NEGOTIABLE)

**Decision**: Трёхуровневая защита UI-потока:
1. **Web Worker** для всех криптовычислений. Worker'ы создаются через нативный
   `new Worker(new URL('./crypto.worker', import.meta.url))` (поддерживается
   сборщиком Angular на базе esbuild). Воркер вызывает WebCrypto и `@noble`.
2. **`debounceTime(500)`** на потоках ввода SSID и пароля (RxJS) — тяжёлый
   пересчёт ключей не стартует на каждое нажатие клавиши.
3. **Кнопка «Пересчитать ключи»** как явный режим для пользователей, которым
   нужен полный контроль над моментом запуска вычислений (дополняет debounce, а
   не заменяет его).
- Каждый расчёт получает токен поколения (generation id); при изменении входа
  старый расчёт отменяется (`AbortController` / игнор устаревшего ответа воркера),
  что реализует FR-009.

**Rationale**: Сочетание выноса в воркер + debounce + явной кнопки гарантирует
отсутствие фризов даже при вводе текста во время PBKDF2(4096) и при переборе
словаря в Модуле 3. Полностью покрывает FR-008, FR-009 и SC-003 (<100 мс отклик).

**Alternatives considered**:
- Только `async` WebCrypto в главном потоке — отклонено: маршалинг больших
  массивов и оркестрация всё равно дают микрофризы; воркер чище изолирует.
- Разбиение на чанки через `requestIdleCallback` — отклонено: WebCrypto уже
  атомарно-асинхронен, воркер проще и предсказуемее.

## R3. Статус атак на npm и защита цепочки поставок (явный запрос пользователя)

**Вопрос пользователя**: «исправили или ещё нет?»

**Вывод: НЕ исправлено в смысле "угроза закрыта" — это продолжающаяся кампания.**

- **Сентябрь 2025 — инцидент chalk/debug**: аккаунт мейнтейнера был
  фиширован (поддельный домен `npmjs.help`), опубликованы вредоносные версии 18+
  пакетов (`chalk@5.6.1`, `debug@4.4.2`, `ansi-styles@6.2.2`, `strip-ansi@7.1.1`,
  `color-convert@3.1.1`, `color-name@2.0.1`, `duckdb@1.3.3` и др.). Полезная
  нагрузка — браузерный стилер крипто-кошельков. **Этот конкретный инцидент
  устранён за ~2 часа**: чистые версии восстановлены, вредоносные сняты. Риску
  подвержены только установки, сделанные в окне ~13:00–15:30 UTC 08.09.2025.
- **Shai-Hulud (сент. 2025) и Shai-Hulud 2.0 «The Second Coming» (24.11.2025)**:
  самораспространяющийся червь. Версия 2.0 запускает вредонос через **preinstall**
  lifecycle-скрипт (срабатывает ещё до завершения установки, даже при её провале).
  Заражено ~796 npm-пакетов, 25 000+ GitHub-репозиториев, утекло ~14 000
  секретов. Деструктивен: при невозможности распространиться/выгрузить данные
  пытается удалить домашний каталог пользователя.
- **Март–апрель 2026** — компрометация `axios`.
- **19 мая 2026 (за день до составления плана)** — группа «TeamPCP» в рамках
  волны Mini Shai-Hulud за 22 минуты опубликовала 300+ вредоносных версий в
  323 пакетах.

Описание пользователя («захватили, код не правили, добавили вредонос в
зависимость с автозапуском через post/after-install») точно соответствует
семейству Shai-Hulud. **Кампания активна; новые волны выходят регулярно.**

**Decision — защитные меры, встроенные в проект:**

1. **`.npmrc` в репозитории** со следующими ключами:
   - `ignore-scripts=true` — блокирует главный вектор (lifecycle-скрипты
     pre/post/install). После включения проверить, что сборка Angular проходит
     (esbuild-сборщик Angular работает без install-скриптов; нативных модулей с
     обязательным build-скриптом в стеке нет).
   - `min-release-age=7` — «карантин»: не ставить пакеты, опубликованные менее
     7 дней назад. **Значение в ДНЯХ** (подтверждено по докам npm CLI v11; требует
     npm ≥ 11.10.0). Именно в этом окне активны и ещё не отозваны новые волны
     (волна 19.05.2026 была бы заблокирована; при установке карантин отсёк свежий
     Angular 21.2.13 → взята выдержанная 21.2.12).
   - `audit=true`, `fund=false`.
2. **Точное пиннингование версий** — без `^`/`~` в `package.json`; обязателен
   закоммиченный `package-lock.json`; установка только через `npm ci`.
3. **`npm audit` и `npm audit signatures`** — в локальном workflow и в CI;
   проверка криптографических подписей реестра.
4. **Минимизация числа зависимостей** — runtime-зависимости только Angular,
   Tailwind, `@noble/curves`, `@noble/hashes`. Чем меньше дерево — тем меньше
   поверхность атаки.
5. **Проверка `hasInstallScript`** — при ревью `package-lock.json` отмечать любую
   зависимость с install-скриптами.
6. **Аудит выбранных версий перед фиксацией** (см. R4): использовать только
   зрелые, давно опубликованные релизы, прошедшие «отлёжку».

**Rationale**: Принцип IV и технические стандарты конституции требуют
браузерного офлайн-приложения без утечки данных пользователя; разработческая
цепочка поставок — отдельный, реальный вектор, и пользователь явно попросил его
закрыть. Меры выше — текущая отраслевая рекомендация (ignore-scripts + cooldown +
пиннинг + lockfile + `npm ci` + audit).

**Alternatives considered**:
- `pnpm` с `minimumReleaseAge` — отличная альтернатива, но пользователь задал
  Node/npm-стек; эквивалентная защита достигается через `.npmrc` npm ≥ 11.10.0.
- `ignore-scripts` только в CI — для данного проекта нативных build-скриптов нет,
  поэтому включаем и в репозитории `.npmrc`; если какой-то инструмент потребует
  скрипт, исключение делается точечно и документируется.

## R4. Версии стека (с учётом «отлёжки» из R3)

**Decision** (точный пиннинг, все версии — зрелые релизы):

| Компонент | Версия | Примечание |
|-----------|--------|------------|
| Node.js | 24.13.0 LTS | Активная LTS-линия; используется только для сборки/тулинга |
| TypeScript | 5.9.3 | В peer-диапазоне Angular 21 (`@angular/build` требует `>=5.9 <6.0`) |
| Angular (framework) | 21.2.12 | Стабильная 21.2.x. Свежие 21.2.13 / Angular 22 не берём — не прошли «отлёжку» (R3); карантин `min-release-age` сам отсёк 21.2.13 |
| Angular CLI / build | 21.2.10 | Выдержанная пара тулинга (>7 дней) |
| RxJS | 7.8.2 | Поставляется как peer-зависимость Angular 21 |
| Tailwind CSS | 4.3.0 + `@tailwindcss/postcss` 4.3.0 | Стабильная ветка v4 (CSS-first конфигурация) |
| `@noble/curves` | 2.2.0 | Audited, zero-dependency |
| `@noble/hashes` | 2.2.0 | Audited, zero-dependency; peer от `@noble/curves` |

**Rationale**: «Latest» трактуем как «последняя *зрелая* стабильная версия»:
Angular 21 даёт современный API (standalone-компоненты, signals, новый
build-pipeline) при шести месяцах накопленных исправлений. Это согласуется с
карантинной философией R3 — свежевыпущенный мажор не ставим.

**Alternatives considered**:
- Angular 22 «самый-самый latest» — отклонено по соображениям отлёжки/риска R3.
- Karma как тест-раннер — отклонено: Karma признан устаревшим; используем
  встроенный в Angular 21 тест-раннер (на базе Vitest).

## R5. Управление состоянием и шагами

**Decision**:
- **RxJS `BehaviorSubject`** — для потока «текущий шаг» каждого модуля и для
  единого общего сценария (clarify Q4). `BehaviorSubject` хранит текущее значение
  и выдаёт его новым подписчикам — идеально для пошагового состояния.
- **Angular signals** — для синхронного связывания состояния с шаблонами
  компонентов (Angular 21 — signal-first); мост `toSignal()` между RxJS-потоками и
  сигналами.
- Единый общий сценарий — в сервисе `ScenarioStateService` (`BehaviorSubject`);
  локальные переопределения параметров модуля (clarify Q4) — отдельный слой
  поверх, мерджится с общим сценарием при чтении.
- Авто-проигрывание (clarify Q3) — таймер на базе RxJS (`interval` +
  `takeUntil`), общий для всех модулей; play/pause/скорость.

**Rationale**: Пользователь явно указал RxJS `BehaviorSubject`. Сигналы — текущий
идиоматичный способ Angular 21 рендерить состояние; связка `BehaviorSubject` +
`toSignal()` даёт и реактивный поток, и удобный шаблонный доступ.

**Alternatives considered**: NgRx — отклонено как избыточное для приложения из
3 модулей (Принцип I — простота); чистые signals без RxJS — отклонено, т.к.
`debounceTime`, `interval`, отмена расчётов естественнее на RxJS-операторах.

## R6. Анимации передачи данных

**Decision**: **Angular Animations** (`@angular/animations`) для визуализации
перемещения пакетов (ANonce, SNonce, MAC, commit/confirm-элементы) между точкой
доступа и клиентом; SVG-слой для схем «вход → преобразование → выход».

**Rationale**: Указано пользователем; нативно для Angular, декларативные
триггеры состояний хорошо ложатся на пошаговую модель (шаг = состояние анимации).

**Alternatives considered**: CSS-only переходы — отклонено: сложнее
синхронизировать с пошаговым state-машиной; сторонние animation-библиотеки —
отклонено (лишняя зависимость, R3).

## R7. Эталонные тестовые векторы (FR-017, SC-007)

**Decision**: Корректность чисел проверяется юнит-тестами против эталонов:
- **WPA2**: классический известный вектор IEEE 802.11i (passphrase
  `"password"`, SSID `"IEEE"` → известный PMK), а также вектор PTK/MIC из
  тест-наборов рукопожатия 4-Way. Хранится в `tests/vectors/wpa2.vectors.ts`.
- **WPA3 SAE**: тестовые векторы SAE/H2E для группы 19 (P-256) из приложений
  RFC по SAE hash-to-element. Хранится в `tests/vectors/sae.vectors.ts`.
- **Формат 22000**: структура строки `WPA*<type>*<mic|pmkid>*<apmac>*<stamac>*
  <essid>*<anonce>*<eapol>*<messagepair>` (type `01`=PMKID, `02`=EAPOL) —
  проверяется на разбор/сборку полей.

**Rationale**: Конституция требует совпадения с эталонными векторами для WPA2 и
(после clarify Q1) WPA3. Векторы фиксируются в репозитории как «золотой эталон».

**Alternatives considered**: Генерация векторов «на лету» другой библиотекой —
отклонено: эталон должен быть статичным и независимым от нашего же кода.
